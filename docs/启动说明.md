# 启动说明

按顺序做完即可跑起来。全部命令在项目根目录执行。

---

## 一、环境要求

| 组件 | 版本 | 检查命令 |
| --- | --- | --- |
| JDK | 17 | `java -version` |
| Maven | 3.8+ | `mvn -v` |
| PostgreSQL + pgvector | 16 + 0.6+ | `psql --version` |
| Node.js | 18+ | `node -v` |
| Python | 3.11+（推荐引擎与 AI 服务） | `python --version` |
| uv | 0.5+ | `uv --version` |

Hadoop 不是必需的：项目在 HDFS 连不上时会自动回退本地文件系统。
AI 服务也不是必需的：不启动时 `/api/ai/*` 返回 503，其余功能不受影响。

---

## 二、配置环境变量

复制模板并填写：

```bash
cp .env.example .env
```

**最少要填两项**（不填会启动失败或连不上库）：

```bash
export DB_PASSWORD='你的PostgreSQL口令'

# JWT 密钥必须 ≥32 字节
export JWT_SECRET="$(openssl rand -base64 48)"
# Windows PowerShell:
# $env:JWT_SECRET = [Convert]::ToBase64String((1..48 | %{Get-Random -Max 256}))
```

可选：

```bash
export AI_SERVICE_BASE_URL=http://localhost:8090
export AI_INTERNAL_TOKEN='change-me-internal-token'   # 与 ai-service/.env 一致
export HADOOP_EXPORT_ENABLED=false    # 没装 Hadoop 时建议关闭定时导出
export RECOMMENDATION_PYTHON='../recommendation/.venv/Scripts/python.exe'  # 夜间推荐任务用的 Python 3.11
export CORS_ALLOWED_ORIGINS=http://localhost:3000
```

## 三、初始化数据库

> ⚠️ **`sql/init.sql` 会 DROP 并重建 `recommend_db` 下的全部表。**
> 库里已有数据时先备份，否则会清空。

```bash
# 1) 备份（可选，但强烈建议）
pg_dump -d recommend_db > backup_$(date +%F).sql

# 2) 建库 + 建表 + 种子数据
createdb recommend_db
psql -d recommend_db -f sql/init.sql
```

如果不想影响现有库，先建一个临时库：

```bash
createdb my_tmp_db
psql -d my_tmp_db -f sql/init.sql
```

验证：

```bash
psql -d recommend_db -tAc "SELECT COUNT(*) FROM materials;"   # 应为 31
```

## 四、启动后端

```bash
cd backend
mvn spring-boot:run
```

或者打包后运行：

```bash
cd backend
mvn clean package -DskipTests
java -jar target/study-recommend-1.0.0.jar
```

看到 `Tomcat started on port 8080` 即成功。

验证：

```bash
curl http://localhost:8080/api/categories
```

### 常见启动失败

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `未配置 JWT_SECRET` | 没设环境变量 | `export JWT_SECRET=...`（≥32 字节） |
| `JWT_SECRET 过短（当前 N 字节）` | 密钥太短 | 换更长的随机串 |
| `Access denied for user 'root'` | 口令不对 | 检查 `DB_PASSWORD` |
| `Unknown database 'recommend_db'` | 没导入 sql/init.sql | 做第三节 |
| `Schema-validation: missing table` | 表结构不全 | 再执行一次 `sql/init.sql` |
| 端口被占用 | 8080 有别的进程 | 加 `-Dserver.port=18080` |

## 五、启动前端

```bash
cd frontend
npm install
npm run dev
```


## 六、运行推荐引擎（可选）

不做这一步系统也能用，只是推荐列表会退化成「按浏览量排序的热门榜」。

```bash
cd recommendation
uv venv --python 3.11 .venv
uv pip install -r requirements.txt

export DB_PASSWORD='你的PostgreSQL口令'

.venv/Scripts/python run_recommendation.py                 # 全量刷新所有用户
.venv/Scripts/python run_recommendation.py --user-id 2     # 只刷新指定用户
```

脚本会把结果写回 `recommendations` 表，随后刷新页面即可看到个性化推荐。

想让它自动跑：后端每天 2:00 会用 `ProcessBuilder` 调一次这个脚本
（`recommendation.python-script` 配置项，默认 `../recommendation/run_recommendation.py`）。
这要求后端进程的 `PATH` 里能找到 `python` 命令。

## 七、Hadoop（可选）

不装 Hadoop 时，`HdfsService` 会自动回退到本地 `backend/storage/`，
所有上传下载与导出功能照常可用。

装好集群后设置：

```bash
export HADOOP_URI=hdfs://your-namenode:9000
export HADOOP_USER=hadoop
export HADOOP_EXPORT_ENABLED=true
```

导出结果（Hive 风格分区目录）：

```
/recommend/warehouse/user_behaviors/dt=2026-05-08/user_behaviors-20260508-181214.csv
```

手动触发：

```bash
# 需要管理员 token
curl -X POST http://localhost:8080/api/admin/hadoop/export -H "Authorization: Bearer <token>"
```

### 跑 MapReduce 热度聚合（可选）

导出之后可以跑「资料热度」的 MapReduce 作业，并与 PostgreSQL 直接聚合做耗时对比：

```bash
curl -X POST "http://localhost:8080/api/admin/hadoop/benchmark?topN=10"      -H "Authorization: Bearer <token>"
```

返回里会包含两条链路的 TopN、各自耗时、`resultsMatch`（结果是否一致）和 `mode`。

### 在真实 Hadoop 集群上跑（可选）

代码已支持 HDFS 输入、YARN 提交与多 reducer。先确保 `HADOOP_CONF_DIR` 指向集群配置，再设置：

```bash
export HADOOP_CLUSTER_INPUT=/recommend/warehouse/user_behaviors
export HADOOP_CLUSTER_OUTPUT=/recommend/warehouse/hotness
export HADOOP_CLUSTER_REDUCERS=4
```

两种触发方式：

```bash
# 1) 直接提交（推荐；输出目录必须不存在）
mvn -DskipTests package
hadoop jar backend/target/study-recommend-1.0.0-hadoop-job.jar \
  /recommend/warehouse/user_behaviors /recommend/warehouse/hotness 10 4

# 2) Spring 管理端：与 PostgreSQL 聚合并对比
curl -X POST "http://localhost:8080/api/admin/hadoop/benchmark-cluster?topN=10" \
  -H "Authorization: Bearer <token>"
```

> 不要用 `study-recommend-1.0.0.jar` 提交：它是 Spring Boot 可执行 jar，`hadoop jar` 会跑
> `JarLauncher` 而不是作业。JDK 17 下还需要给 YARN 容器加
> `JAVA_TOOL_OPTIONS=--add-opens=java.base/java.lang=ALL-UNNAMED`（Hadoop 3.3.6 官方推荐 JDK 11）。
>
> 单机伪分布式（Ubuntu 24.04 + Hadoop 3.3.6 + JDK 17、4 reducers、2000 行）已实测通过，
> 作业约 27 秒；多节点集群的扩展性数字仍需自行采集。

**Windows 用户注意**：Hadoop 在 Windows 上需要 `winutils.exe` 与 `hadoop.dll`，
否则会报 `HADOOP_HOME and hadoop.home.dir are unset` 或
`UnsatisfiedLinkError: NativeIO$Windows.access0`。配置方式见 README 5.5。

未配置时接口**不会报错**，而是退回进程内等价实现（`mode=IN_PROCESS`），
结果一致但耗时不能用来比较 Hadoop 与 PostgreSQL —— 返回体里的 `conclusion` 会写明这一点。

> Windows 下没有配置 `HADOOP_HOME` 时会打印 `winutils.exe` 警告，
> 属于正常现象，不影响本地回退模式。

## 八、AI 服务（可选，FastAPI + LangGraph + vLLM + pgvector）

不启动 AI 服务时，其余功能不受影响，`/api/ai/*` 会返回 503 和明确提示。

### 8.1 用 Compose 起数据库与服务

```bash
# 项目根目录
docker compose up -d postgres ai-service

# 有 GPU 再起两个 vLLM（对话 + 向量）
docker compose --profile gpu up -d vllm-chat vllm-embed
```

### 8.2 不用 Docker 时

```bash
# 1) PostgreSQL + pgvector
docker run -d --name study-pg -p 5432:5432 \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=study_ai pgvector/pgvector:pg16

# 2) vLLM（需要 GPU）
vllm serve Qwen/Qwen2.5-7B-Instruct --served-model-name qwen2.5-7b-instruct --port 8000
vllm serve BAAI/bge-m3 --task embed --served-model-name bge-m3 --port 8001

# 3) AI 服务
cd ai-service
cp .env.example .env      # 修改 DATABASE_URL / VLLM_BASE_URL / VLLM_EMBEDDING_BASE_URL / AI_INTERNAL_TOKEN
uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 8090
```

### 8.3 建立索引

```bash
curl -X POST http://localhost:8090/internal/v1/index/rebuild \
  -H "X-Internal-Token: change-me-internal-token"
curl http://localhost:8090/internal/v1/index/stats \
  -H "X-Internal-Token: change-me-internal-token"
```

之后资料的新增/修改/审核/删除会自动异步同步；也可以由管理员手动重建：

```bash
curl -X POST http://localhost:8080/api/admin/ai/reindex -H "Authorization: Bearer <ADMIN_TOKEN>"
```

### 8.4 没有 GPU 时

用假模型先验证链路：

```bash
cd ai-service
uv run python scripts/stub_vllm.py --port 18000
# .env 中设置 VLLM_BASE_URL=http://127.0.0.1:18000/v1、VLLM_EMBEDDING_BASE_URL 留空、EMBEDDING_DIM=8
uv run python scripts/smoke_e2e.py     # 全链路冒烟：pgvector + stub + 真实 uvicorn
```

### 8.5 常见问题

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `AI 服务未启用` | Spring 没配 `AI_INTERNAL_TOKEN` 或地址 | 两边配置同一个令牌 |
| `内部令牌无效`（401） | 两边令牌不一致 | 对齐 `AI_INTERNAL_TOKEN` |
| `LLM_UNAVAILABLE`（503） | vLLM 没启动 / 端口不对 | 检查 `VLLM_BASE_URL` 与 `/v1/models` |
| `embedding 维度 N 与配置不一致` | 换了 embedding 模型 | 修改 `EMBEDDING_DIM` 并清空 `ai_material_chunks` 重建 |
| 索引为空 | 没跑 rebuild，或 Spring 未启动 | 先起 Spring，再 `POST /internal/v1/index/rebuild` |
